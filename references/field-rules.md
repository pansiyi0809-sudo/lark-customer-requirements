# 字段与流程规则

## 配置与依据

- `config.local.json` 保存目标 Base 链接、可选的优先级规范链接和“临时需求”默认值。它由每位使用者在本机创建，不能发布。链接只定位资源，不授予访问权限；写入前始终用当前飞书用户身份读取实时 schema。
- 下列 24 个字段是本 Skill 支持的需求表模板。若目标表的字段名或结构不同，先修改字段规则和脚本，再发布为新的版本；不要猜测字段映射。
- 优先级按配置的规范文档和客户影响判断，不把“希望尽快”直接等同最高优先级。计划上线时间须在研发评估后确定；客户期望不等于上线承诺。

## 字段

| 字段 | 填写规则 |
| --- | --- |
| 子中心 | 必须与目标表实时选项一致，按实际归属选择。 |
| 功能名称 | 简短、可检索；独立需求各有名称。 |
| 功能描述 | 一句话说明核心能力或问题及适用范围，子功能可简要并入。 |
| 进展 | 按实际阶段选择实时选项；刚取得且未评估的需求选对应“待评估”阶段。 |
| 优先级 | 只填等级；判断依据留在对话或草稿中。 |
| 产品负责人 / 研发负责人 / 测试负责人 | 至少一位适用负责人；从实时选项选取，不从录音昵称或文件名猜人。 |
| 计划提测时间 / 计划上线时间 / 实际提测时间 / 实际上线时间 | 有确定日期再填；不确定留空。 |
| 上线版本 | 确定后从实时选项填写。 |
| 测试环境走查 / 生产环境走查 / 本次是否走查 | 有结论才填，未知留空。 |
| 详情备注 | 只有需要留给执行者的已确认信息才填。 |
| 需求背景 | 按模板写“提出人：姓名”；姓名未知先询问，不写占位符。 |
| 需求来源 | 从实时选项选择与需求性质相符的值。 |
| 临时需求 | 使用本地配置中与实时表格一致的默认值；有明确证据才改变。 |
| 附件 | 用户同意上传时使用附件专用命令。 |
| 需求ID | 系统生成的只读公式；不写入。 |
| 父记录 | 确知关联记录 ID 时才填。 |
| 情况说明 | 仅填需要在表内保留的已确认事实。 |

## 写入约束

实时 schema 决定字段是否存在、是否必填、字段类型和选项全集。`select` 用当前选项名称数组提交，即使是单选；`user` / `link` 用已核实的 ID；日期按 Base 时区；公式、系统字段和附件不能当作普通单元格写入。若选项同名，提交后回读核对。截图和示例都不能代替实时 schema。
